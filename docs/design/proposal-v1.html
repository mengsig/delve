Design review / 01

Two ways into the same material.

Recommend Contour. Keep the map in view, teach one decision at a time, and let a learned concept change what appears next. For a repository, a PR is a reason to revisit a changed edge—not to start over. For another topic, a live exercise does the same work.

A / Recommended

Contour

A terrain map for relationships. A wide instrument panel for lessons. Best for asking “what connects to this?”

B / Alternative

Folio

A dependency ledger instead of terrain. An evidence margin beside the lesson. Easier to scan; less spatial memory.

Design review / 02

A lesson is data. A lab is a place to act.

Ask the agent for a versioned JSON document, not a complete page. Delve owns the type, layout, navigation, keyboard support and motion. An environment is one block: the agent can author a new simulation without owning the desktop or the learner record.

Try the evidence loop

In the worker lab, accept the old worker’s result. In the exposure lab, capture the rider with a slow shutter. Inspect the specific follow-up on each atlas; neither action declares the whole topic weak.

One envelope; different instruments

Environment manifest: runtime/version, pack ID or content-addressed bundle, typed initial state and allowed inputs, event schema, assessment rubric, accessible fallback. Never take a file path or command from a lesson.

Evidence flow: learner action → bounded observation → host-verified fact → tentative diagnosis → suggested exercise. The agent sees a consented summary, not raw keystrokes. Ignore malformed, duplicate or late events. No event may write mastery itself.

What gets rendered

Prose becomes a reading section. A diagram becomes labelled relationships. A code block carries its snapshot and highlight spans. A lab gets an isolated stage. A check offers a short explanation, not a score.

Whole lesson invalid? Preserve the last valid version and offer retry. Unknown optional block or a timed-out lab? Show its fallback, mark it unavailable and collect no evidence. Never pretend an unavailable exercise was passed.

How a third topic gets a completely new instrument
A network builder, without a network-builder screen.
An agent could generate a canvas for wiring a client, proxy and service. A future manifest selects bundle: {sha256, entry, apiVersion} instead of a built-in pack. The bytes arrive with the lesson and are verified locally; the guest cannot fetch dependencies. The host supplies a seed topology and a bounded set of simulated ports—not real sockets.
Dragging a link emits link.added {fromPort, toPort}. The host validates IDs and reconstructs the simulated path. A versioned declarative rubric compares that trace with the exercise goal. The agent can suggest a proxy-routing exercise with the supporting event IDs. If the host cannot independently verify a new rubric, keep it as a learning suggestion, never mastery evidence.

Design review / 04
One local desktop, two trust boundaries.
Delve is proposed as an open-source, single-user desktop app. These are design boundaries, not a security certification. Local-first means lessons and progress remain readable offline; generating new work may send approved excerpts to the chosen provider.
01 · Store and present
Electron main owns one SQLite database: workspaces, canonical concepts, prerequisite edges, snapshot bindings, validated lessons and per-depth evidence. React/Vite + TypeScript renders offline via narrow preload IPC; no production web server. Use React Flow for labelled dependency neighborhoods, stable positions and keyboard focus; offer Folio’s list at every scale.
02 · Read and generate
Read local Git snapshots without hooks or executing project code; fetch PR metadata/diffs with read-only GitHub access (user’s authenticated CLI or scoped token in OS keychain). Missing/truncated diff? Show partial coverage. The approved slice goes to an installed, signed-in codex exec or claude -p adapter using fixed argv, no shell, clean working directory, no write tools or project plugins. Do not copy credentials. Verify subscription mode, provider limits and distribution terms before release; never silently fall back to API billing.
03 · Run untrusted environments
Prefer agent-authored declarative packs. For genuinely novel behavior, use a versioned, hashed bundle in a disposable sandbox process with separate storage, no Node/preload/IPC or secrets, no network, navigation, downloads or native permissions. Host controls input, checks event bounds, rate, source/session and rubric; generated code cannot award credit. Enforce CPU, wall-time, output and memory limits outside the guest; terminate on breach. Ship novel code execution only after containment tests. These demo instruments use authored fixtures in opaque-origin iframes.
04 · Budget and connect
Preview the files, estimated input and one-run limit before sending. Generate only the chosen depth; cache by commit/diff, concept, depth, schema and model. Deduplicate in-flight work, allow cancel, bound retries and stop on quota. Future delve://learn intents or an authenticated opt-in loopback adapter carry a repo ID plus commit, PR or proposed-work reference; preview provenance and ask before import/generation. Archon/Aether suggests; Delve works without either.

Design review / 05
Decisions before the first build.
Primary surface
Approve Contour in both themes; retain Folio as an accessible relationship list. No points, timers, streaks or rank.
Product scope
Lead with repos and changes; keep workspaces, concepts, evidence and environments topic-neutral. Use the camera lab as a cross-domain acceptance test.
Depth and transfer
Default to Medium. Let users switch without changing the concept. Reuse only an exact portable concept at a demonstrated depth; do not mistake a familiar label for mastery of new code.
Lesson authoring
Approve typed blocks plus an open environment manifest, not arbitrary agent-written pages. Start with declarative packs; gate arbitrary bundles on isolation and failure tests.
Evidence and privacy
Accept one optional practical check as local, revisable evidence. Show the reason for a recommendation. Track useful actions only, offer reset and keep peer comparison off by default.
Provider and integration
Use the user’s own installed CLI. Confirm authentication and subscription behavior on each supported OS before promising compatibility. Start with explicit generation and keep Archon/Aether integration optional.
Review assumptions: one person on a desktop; example repos, file spans, PRs and photography tasks are curated fixtures. Switching workspaces, both labs, checks and coverage run locally in this tab. Refresh resets the study. No account, filesystem access, model, paid call, upload or backend.
